# Yakker 1.6.0 — Focus

The Focus interface makes live radio, saved shows, and recording schedules feel
like one player. This release builds on the recording and playback features in
1.5.0; the recording format and controller protocol are unchanged.

## Listening

- Listen, Library, and Schedules form a compact first row, with Settings at the
  right. Up to six favorite stations appear as presets on Listen.
- Play/Pause remains the main control. Stop sits directly below it, between
  Record and Sleep; the persistent player uses the same hierarchy while browsing
  Library, Schedules, and Settings.
- **Paused · buffering** explains that live audio keeps arriving so you can
  resume your place. **Listening stopped** means the stream is disconnected and
  replay history is cleared. Saved-show playback has separate paused/stopped
  labels and uses the recording's original station artwork.
- Long station titles stay on one line, with a slow return marquee when needed.
  Reduced-motion mode uses an ellipsis and a full-title tooltip.

## Library, schedules, and Settings

- Recording rows show listening progress and a Resume action with the saved
  position. Expanded details group status, duration, size, and capture times;
  restart and confirmed deletion remain secondary actions.
- Schedules show the next upcoming recording first and group paused schedules
  below. Editors use labeled fields, automatic next-recording previews, and clear
  primary actions for weekly, one-time, and immediate recordings.
- Settings opens four tabs: Listening, Storage, Alerts, and Stations. Storage
  Save/Reset actions stay with storage; notification switches apply immediately.
  The custom-station editor has permanent field labels and quieter secondary
  actions. Closing Settings restores the prior section and scroll position.
- Empty libraries, unmatched searches, and connection failures explain the next
  useful action instead of leaving a blank view.

## Consistent controls and a compact bar

- Typography, spacing, hover/focus feedback, search fields, dropdowns, and
  sliders share one treatment. Controls reflow on narrow popups, and short
  popups reserve more room for scrolling content.
- Keyboard focus follows visual order and scrolls fields/actions into view.
  Manual scrolling is respected when the library updates. Sliders share arrow,
  Page Up/Down, and Home/End controls; see the README for step sizes.
- The bar uses smaller station artwork and state icons, with a separate REC
  count. Its tooltip groups station details, playback and buffering status, and
  active recording names.
- New widgets start in **centerEnd**, beside the center island. Existing widgets
  keep their saved position and preferences.

See the [README gallery](../../README.md) for the current native interface.

## Upgrade

Use the same checkout or extracted folder as your existing managed installation.
Finish active recordings and stop foreground playback before upgrading and
restarting the shell: a shell restart interrupts background captures.

From a source checkout:

```sh
make build
./yakker install
omarchy restart shell
```

Compiled archives already contain both binaries; run `./yakker install` from the
extracted `yakker/` directory, then restart the shell. Recording files, schedules,
custom stations, and saved bar preferences remain in their existing locations.
Live-only playback remains the default for new installations.

## Release files and validation

- `yakker-1.6.0-linux-amd64.tar.gz`
- `yakker-1.6.0-linux-arm64.tar.gz`
- `yakker-1.6.0-source.tar.gz`
- Individual `.sha256` files and `yakker-1.6.0-SHA256SUMS`.

Validation covers Go formatting, vet, module verification, race tests, real mpv
decoding with local fixtures, native recording/playback and keyboard checks, and
68 compact view/size/font combinations plus popover and scroll-return checks.
Both Linux archives include the shared QML controls, refreshed documentation and
screenshots, build information, and third-party license notices. ARM64 is
cross-built and archive-checked; playback on physical ARM64 hardware is not
verified.
