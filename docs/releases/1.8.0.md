# Yakker 1.8.0 — Grouped recordings and curated news radio

Keep recovered recording parts together and browse a curated mix of sports,
news and public radio through the same focused player.

## One library entry per recovered show

- Segments from the same recording occurrence share one library row, with an
  **Interrupted** indicator, part count and total available saved audio.
  Separate episodes of a recurring schedule remain separate shows.
- Expand **Parts** for chronological captures, recorded time ranges, status and
  recovery notes, plus individual playback, restart and confirmed deletion.
  Deleting a part keeps the other parts and their audio files.
- **Resume** opens the last-played unfinished part. After a part finishes, Resume
  selects the next part for you to start. Playback still stops at each part's end;
  this release does not concatenate files or advance automatically.
- Progress and seeking describe the selected part. Interruption markers explicitly
  leave missing-audio duration unknown; process timestamps and file durations
  cannot establish an exact broadcast gap.
- Last-played and completion bookmarks survive restart. Older indexes fall back
  to saved per-file positions until new bookmarks are written. Historic listening
  order cannot be recovered when several old parts have saved progress.
- A missing resume target or next part still recording is shown explicitly.
  Open Parts to choose other available audio. Progress updates preserve keyboard
  focus on the part controls.

Grouping changes presentation and bookmarks. Existing Opus files stay separate,
and recovery does not reconstruct missing source audio.

## Sports, news and public radio

The catalogue now has **37 stations: 24 existing sports stations and 13 news and
public-radio additions**, with official artwork bundled locally:

- Boston: **WBZ NewsRadio 1030**, **WBUR 90.9**.
- New York: **1010 WINS / 92.3 FM**, **WNYC 93.9**.
- Los Angeles: **KNX News 1070**, **LAist 89.3 / KPCC**.
- Chicago: **WBBM Newsradio**.
- Philadelphia: **KYW Newsradio**.
- Detroit: **WWJ Newsradio 950**.
- Denver: **CPR News / KCFR**.
- Minneapolis–St. Paul: **MPR News / KNOW**.
- Seattle: **KUOW 94.9**.
- San Diego: **KPBS 89.5**.

**Change station → All / Sports / News** separates the catalogue. Favorites is an
independent toggle within the current category, and search works alongside both
filters. Custom stations remain available under All and Favorites without being
assigned a format automatically. External station catalogues can omit category.

Result details identify Sports or News, empty states explain category-specific
favorite results, and filter buttons wrap at smaller sizes. Left/Right on a
category button moves from the focused button, including after Tab navigation.
Filtering never tunes a station or starts playback. Public-radio schedules also
include interviews, culture and other programming beyond hard news.

The 13 additions passed short audio-decoding checks from a US connection,
including paced 20-second checks of their published feeds. These are availability
spot checks, not a guarantee of long-session stability or international access.

## A cleaner player and recording shutdown

- Favorites now live exclusively inside the station picker. Saving a station
  does not add a permanent preset row or a second Favorites dropdown below the
  main player. The idle bar radio glyph better matches surrounding shell icons.
- Blocked HLS readers receive a second cooperative interrupt before the existing
  bounded hard-stop deadline. This improves clean reader shutdown while keeping
  finalization bounded; a required hard stop still leaves a partial-recording note.
- Recording audit tools more strictly verify foreground identity and decoder
  progress, distinguish scheduled delivery boundaries from connection-specific
  outer audio, preserve valid PCM references after forced shutdown, and fail
  inconclusive boundary checks instead of treating them as a pass.

Recording quality remains **mono Opus at 24 kbit/s VBR**. Broadcaster buffering,
advertising and connection-specific content can affect file duration and timing.
There is no wake-to-record service; missed source audio remains missing.

## Upgrade and rollback

Finish active recordings and stop foreground playback before installing and
restarting the shell. Install the QML and controller together from the same
checkout or extracted archive, at the existing managed source directory path.
The installer preserves its previous plugin files and refuses to overwrite
unmanaged changes.

**Back up the recording index while recordings are idle:**
`~/.local/share/yakker/recordings.json`, or
`$XDG_DATA_HOME/yakker/recordings.json` when configured.

Version 1.8 reads older recording indexes and keeps existing audio, schedules,
station IDs, favorites, placement and storage settings. Once playback saves the
new last-played/completion fields, **v1.7.0 cannot read that index**. Keep the
pre-upgrade index backup with the old plugin for rollback; the installer's plugin
backup contains code, not recording metadata. Audio added after that backup will
not appear in a restored older index.

From a source checkout:

```sh
make build
./yakker install
omarchy restart shell
```

Compiled archives already include both executables. Run `./yakker install` from
the extracted `yakker/` directory, then restart the shell.

## Release files and validation

- `yakker-1.8.0-linux-amd64.tar.gz`
- `yakker-1.8.0-linux-arm64.tar.gz`
- `yakker-1.8.0-source.tar.gz`
- Individual `.sha256` files and `yakker-1.8.0-SHA256SUMS`.

Validation covers formatting, vet, module verification, race-enabled tests,
real-mpv integration, catalogue and artwork packaging, grouped recording
bookmarks, native UI interaction, compact layouts and keyboard navigation.
Screenshots use the production QML with illustrative data and varied stations;
they do not use private listening or recording data.

Additional acceptance work since 1.7 exercised physical s2idle suspend/resume
and removal/re-enabling of the last widget on one installed host, including
partial audio, linked remainders, playback/resume and process cleanup. Longer
overlapping live captures retained qualifications around an initially forced BBC
reader shutdown and an unconfirmed Seattle start match. The follow-up HLS fix
and stricter audits do not establish sample-perfect broadcast boundaries.

Both Linux archives include build information and dependency license notices.
ARM64 is cross-built and archive-checked; physical ARM64 playback, hibernation
and power-loss recovery remain unverified.
